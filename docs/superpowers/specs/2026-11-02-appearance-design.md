# Оформление: светлая тема и выбор указателя

**Статус:** утверждена пользователем 2026-11-02 вместе с макетом `docs/design/quiet-line-b-light.html`; реализация — план `2026-11-02-appearance`.

**Основа:** вариант B (`2026-11-01-shell-redesign-design.md`, макет `docs/design/quiet-line-b.html`, `DESIGN.md`). Указатель Capitaine добавлен 2026-11-02 коммитом `feat(hyprland): указатель мыши — тема Capitaine`.

## Зачем

Вариант B существует только в тёмном виде. Пользователь хочет светлую тему окружения и удобное переключение указателя (тёмный / светлый Capitaine) в «Настройках» вместо правки `hyprland.lua`.

## Решения пользователя (2026-11-02)

1. **Указатель выбирается отдельно от темы**: цвет (тёмный / светлый) и размер — свои пункты; тёмный указатель остаётся и при светлой теме.
2. **Тема переключается вручную**, без расписания и восхода/заката: «Светлая / Тёмная» в «Настройках» и быстрая кнопка в пункте управления, применяется сразу.
3. **Светлой становится всё окружение**: оболочка, рамки, тени и заголовки окон Hyprland, схема приложений GTK, Qt и браузеров.
4. **Без Superpowers**: спека, макет на утверждение, план, реализация.
5. По умолчанию — тёмная тема, тёмный указатель 24 px: ничего не меняется, пока пользователь не выберет иное.
6. **Терминал Ghostty тоже следует теме** (отзыв после живой проверки 2026-11-02): установщик дописывает в настройки Ghostty `theme = light:/usr/share/quietline/ghostty/quietline-light,dark:Apple System Colors` — Ghostty сам переключает схему по `color-scheme`. Светлая схема — своя (`config/ghostty/quietline-light`): палитра Apple System Colors Light на сером фоне `#ececef`, как у заголовков окон светлой темы; белый фон пользователь счёл слишком ярким. Строка добавляется, только если своей `theme` в файле нет; файл — `config.ghostty`, иначе существующий `config`.

## Где переключается

- **«Настройки» → «Оформление»** — новый раздел (значок `palette`, индиго `#5e5ce6`) в группе с «Экраном и яркостью», сразу после него. На странице: группа «Тема» — две карточки-превью «Светлая» и «Тёмная» 150×96, выбранная — рамка акцентом 3 px; строка-пояснение про приложения. Группа «Указатель» — строка «Цвет» с сегментами «Тёмный / Светлый» (значок стрелки в цвет указателя) и строка «Размер» с сегментами «Обычный / Крупный / Очень крупный» = 24 / 36 / 48 px (номинальные размеры, которые есть в Capitaine; Hyprland сам умножает на масштаб монитора).
- **Пункт управления** — в заголовке модуля «Экран» справа кнопка-капсула «Тёмная тема» (значок `dark_mode`): залита акцентом, когда тема тёмная; щелчок переключает тему. Отдельной плитки нет: сетка плиток остаётся 3 × 2 **(решение агента)**.

Те же размеры, радиусы, шрифты и движение; меняются только цвета (значения — макет `quiet-line-b-light.html`, после утверждения — `DESIGN.md` и `Theme.qml`):

Цвета, которые сейчас вписаны прямо в QML (около 40 мест вне `Theme.qml` и экрана блокировки), становятся токенами `Theme.qml`. **Экран блокировки общий для обеих тем**: белый текст поверх размытого и затемнённого снимка экрана читается на любых обоях (решение агента). Цвета разделов в боковой панели «Настроек» и текст на акценте (`accentForeground`) — те же в обеих темах.

**Hyprland в светлой теме:** рамка активного окна `rgba(007affd9)`, неактивного `rgba(0000001a)`; тень `rgba(0000002e)` / `rgba(00000017)`; hyprbars — фон `rgb(ececef)`, текст `rgba(000000c7)`, значки кнопок `rgba(0000009e)`, кружок под указателем у «развернуть» и «свернуть» `rgba(00000014)` с тёмным значком; «закрыть» — тот же красный `#e5484d` с белым значком.

## Как устроено

**Хранение.** `$XDG_CONFIG_HOME/quietline/appearance.json` — `{"version": 1, "theme": "dark" | "light", "cursor": "dark" | "light", "cursorSize": 24 | 36 | 48}`. Рядом `appearance.lua` — та же таблица для конфигурации Hyprland (по образцу `display.json` / `display.lua`). Нет файла — значения по умолчанию.

**CLI.** `quietline-shell appearance [--set JSON] [--path PATH]` → `{"theme", "cursor", "cursorSize"}`; `--set` принимает часть полей, проверяет, пишет оба файла (сначала `.lua`, последним атомарно `.json`) и применяет, в ответ добавляется `"applied": true | false`. Применение:

1. `gsettings set org.gnome.desktop.interface color-scheme prefer-dark | prefer-light` — схема для GTK 4 / libadwaita, Chrome, Firefox, Electron и Qt через портал настроек (`xdg-desktop-portal-gtk` уже в основе); `gtk-theme Adwaita-dark | Adwaita` — для GTK 3, который `color-scheme` не читает.
2. `hyprctl reload` — Hyprland перечитывает конфигурацию: `quietline.lua` берёт цвета рамок, теней и hyprbars и `XCURSOR_THEME` / `XCURSOR_SIZE` из `appearance.lua`. Перезагрузка, а не `hyprctl eval`: кнопки hyprbars добавляются вызовом `add_button`, и повторный вызов на лету их бы удвоил; при перезагрузке плагин собирает кнопки заново.
3. `hyprctl setcursor capitaine-cursors[-light] SIZE` — указатель меняется сразу; Hyprland сам передаёт его в gsettings (`cursor.sync_gsettings_theme`).

`applied` — `true`, только если все три шага вернули код 0; вне сеанса Hyprland шаги 2–3 пропускаются и `applied` — `false` (тема применится при входе: `quietline.lua` читает `appearance.lua` при загрузке, gsettings хранятся в dconf).

**Оболочка.** Новый синглтон `Appearance.qml` (по образцу `Lang.qml`): читает `quietline-shell appearance` при старте, `update(changes)` пишет через `--set` и перечитывает. `Theme.qml` отдаёт токены по `Appearance.light` — все поверхности перекрашиваются сразу, с плавным переходом цвета `motionDuration` там, где он уже анимируется. Экран блокировки берёт из `Theme` только шрифты и цвет выделения текста, его цвета от темы не зависят.

**Hyprland.** `quietline.lua` читает `appearance.lua` так же, как `display.lua` (`pcall(dofile, …)`, проверка типов, без файла — тёмная тема) и выбирает таблицу цветов. `hl.env("XCURSOR_THEME", …)` в `hyprland.lua` после подключения Quietline по-прежнему главнее.

## Что не входит

- Свои настройки цветов VS Code, Telegram и других программ с отдельной темой: они следуют `color-scheme` только при собственной настройке «как в системе»; их конфигурации Quietline не меняет (исключение — Ghostty, решение 6).
- Программы KDE (Dolphin) берут цвета из схемы KDE (`kdeglobals`), а не из `color-scheme`: без пакетов Plasma они остаются в своей схеме по умолчанию. Переключение схемы KDE — отдельная задача после живой проверки.
- Обои: у Quietline своих обоев нет.
- Автоматическое переключение по времени — отклонено пользователем (решение 2).

## Риски и проверки

- `hyprctl reload` перечитывает всю конфигурацию: проверить вживую, что окна, режимы движка, масштаб мониторов, раскладки и hyprbars после него те же, а кнопки заголовка не удваиваются.
- Портал отдаёт `color-scheme` программам сразу; Chrome и GTK 4 меняются на лету, GTK 3 — частично (уже открытые окна могут не перекраситься).
- Модульные тесты: `quietline-shell appearance` (чтение, частичная запись, неверные значения, `appearance.lua`, шаги применения через подменённые команды), контраст токенов не проверяется тестом — оценивается вживую. Живая проверка — новые пункты в `scripts/smoke-shell-redesign.md` и `docs/backlog.md`.
